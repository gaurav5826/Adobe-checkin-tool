# Self-Review Checklist

Run this before presenting drafts. Two passes; iterate until both are clean.
Fix wording gaps yourself; surface real *work* gaps to the user honestly.

## Pass 1 — Senior engineer (accuracy & taste)
- Every claim traces to real evidence (ticket / PR). Nothing overstated.
- In-progress work is labeled in-progress; **nothing unshipped is claimed as done.**
- **No vanity metrics in the prose** — no self PR counts ("I merged N PRs"), no
  brag denominators ("only 1 revert", "1 reopened ticket").
- No invented numbers. If a metric isn't in the evidence, omit it or ask.
- No internal release version numbers / release counts in the prose.
- Routine ceremonies (testathon, standups) are folded into quality — not called
  out as separate achievements.
- Q3 asks are level-appropriate (see content-preferences).
- Tone soft/professional. Numbers live in the Evidence sheet, not the prose.
- No confidential data anywhere it shouldn't be.

## Pass 2 — Manager (calibration)
- Does each point **lead with impact/outcome**, not activity?
- Map evidence to **Strategy / Execution / Leadership** — is each represented?
- **Rate it honestly:** is this above-average / genuinely notable, or solid-but-
  routine? Name specifically what's special (or admit it's standard). Don't
  inflate — inflation gets torn apart in calibration.
- Identify the **1–3 gaps** between the current level and the next, and say
  whether each is a *wording* gap (fixable here) or a *real-work* gap (for the
  user to close next cycle).

## Loop
Apply fixes, re-run both passes. Stop when Pass 1 is clean and Pass 2 has nothing
left but real-work gaps (which belong to the user, not the document).
